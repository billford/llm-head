## Unrelated finding: `procs` alerts flap on the GPU hosts and lampoon

During the post-reboot checks, `procs` showed lampoon CRITICAL (479) and european
WARNING (283).

The cause is a monitoring setup problem, not the cutover. The agents on lampoon, xmas
and european still include their local `conf.d`, which defines its own `procs` service
with the default thresholds (250/400). The master's `procs` uses 600/800. Both report
under the same service name, so the state flips depending on which result arrived last.
lampoon's ~480 processes are normal: they're almost all kernel threads on a 32-core host,
including 32 `jfsCommit`.

The fix is the standard one for agents: remove `include_recursive "conf.d"` from each
agent's `icinga2.conf`. This is left for the owner to decide.
